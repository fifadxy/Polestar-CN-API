# 04｜数字钥匙研究的安全边界与验收

## 威胁模型

这是能授予接近、开门和启动车辆权限的高风险认证系统，与普通 C3/PCCS 远程命令不同。

- 禁止把官方 App 的 `private key`、原始数字钥匙缓存、Keystore 数据、真实已配对凭证、真实挑战/响应记录复制进第三方工程。
- 禁止伪造车端确认、绕开 OEM SDK 许可验证、重签官方 App 以冒充受信任客户端或禁用车辆认证。
- 任何测试环境不得使用生产密钥、实际 VIN、账号密码、OAuth code、令牌、手机号、设备唯一标识或位置。
- 代码仓库不提交 APK、DEX、SO、`.der`、`.pfx` 或 SDK 私有二进制。
- SDK 包中存在 `InvalidLicense` 类仅说明异常类型存在；不能据此推导必须绕过或已验证实际阻断。

## 验收矩阵

| 能力 | 静态确认 | 模拟器确认 | 真正数字钥匙 |
| --- | --- | --- | --- |
| PAK UI 类和 SDK 类存在 | YES | 不需要 | NO |
| P319 SDK / Volvo 调用关系 | YES（启发式交叉核验待办） | 不需要 | NO |
| 系统 BLE 权限声明 | YES | PENDING | NO |
| 原签名安装/启动 | 不适用 | PENDING | NO |
| 后台重启/连接错误处理 | 部分类存在 | PENDING | NO |
| OEM SDK 可分发许可 | UNKNOWN | 模拟器无法证明 | NO |
| 新设备独立生成、绑定钥匙 | UNKNOWN | 模拟器无法证明 | NO |
| 车辆接受独立数字钥匙 | UNKNOWN | 模拟器无法证明 | NO |
| 本人授权车辆无感进入/启动 | UNKNOWN | 不适用 | NO |

测试分层：`APK_CONFIRMED`、`LAB_VERIFIED`、`EMULATOR_VERIFIED`、`OEM_AUTHORIZED`、`VEHICLE_VERIFIED` 分别管理。只有 `VEHICLE_VERIFIED` 可以宣称实际数字钥匙可用。具体密钥材料与验证过程不得入库。

## APP 设计要求

- 数字钥匙独立模块、不可与远程解锁命令状态混为一谈。
- 默认禁用任何可影响车端配对/认证的调用。
- 手动确认车辆及授权后才展示配对入口；未持有 OEM 合法集成则标为 unavailable。
- 可以显示官方数字钥匙的管理引导，但不得宣称与 OEM 正式授权无差别。
- 退出登录要正确清理自研 APP 的状态，不能删除官方 APP 的钥匙。
- 未能确认手机具备 BLE 或后台权限时提示，不把能力误判为已配对。
