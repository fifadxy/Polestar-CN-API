# 21｜v0.7.4 两套皮肤、详细风格重排、动态 VI 与空调剩余时间

## 两套皮肤

设置 → 界面皮肤现在只提供：

1. **简洁风格**：原“此刻图片风格”的方向，保留大续航、车辆主视觉、圆形核心控制和高密度状态。
2. **详细风格**：原“当前版本”，用于同时查看更多车辆数据、辅助状态和远程控制。

历史值自动迁移：`latest` / `ev_concept` → 简洁风格；`current` → 详细风格。

## 详细风格布局

- 顶部车辆名称使用 `VehicleInfo.displayLabel()`，完整显示车型、年款及 VIN 后4位；
- 电量 / 续航与用户选择的数据位于车辆图上方；
- 原先分散在顶部的 **车窗、鸣笛/闪灯、门窗、胎压、露营** 全部移动到车辆图下方；
- 门锁、驻车空调、尾箱、空气净化保持四个核心远控；
- 页面仍为单屏固定布局，并保留顶部下拉刷新。

## 控制页数据显示

设置统一为“车辆控制页数据显示 · 最多 6 项”。两套控制页读取同一 `home_metrics` 选择，因此切换皮肤不会改变用户选择的数据项目。

## 动态 Polestar VI

- 全部自定义交互控件通过统一 click helper 获得 70 ms 压下 + 150 ms 回弹动画；
- 使用约 0.975 缩放和轻微透明度变化，不改变布局尺寸；
- 两套车辆控制页各使用一个 3 dp 的独立橙色呼吸光带；
- 光带只重绘自身区域，2.6 秒低频循环，不做全屏模糊/粒子动画。

## 空调剩余时间

参考 APK DEX 已确认：

| 字段 | 含义 |
|---|---|
| 2 | 空调状态 |
| 3 | 剩余运行分钟 |
| 7 | 车内温度 |
| 8 | 目标温度 |

模板 `climateMetricText` 在空调开启且 field 3 > 0 时显示“剩余 …”，否则显示“剩余时间暂无”。

本项目策略：

1. 优先使用车辆返回的 field 3；
2. 若 field 3 缺失，但本 App 已确认刚执行 climate-start，则使用本机 30 分钟倒计时；
3. 本机回退必须显示“估算/~”，不冒充车辆真实剩余时间；
4. 车内温度、目标温度继续读取 field 7/8。
