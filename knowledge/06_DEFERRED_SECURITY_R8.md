后期启动条件：用户明确要求开始安全工作，并且 API 主流程已稳定；到时单独建立 `security-hardening` 里程碑，不干扰功能分支。

## 双报告新增后期问题池（仍不执行）

- 本地静态签名材料与加密会话设计；参考 APK 的签名协议必须与后端一致，不可擅自“替换 MD5”为其他算法。
- 远控生物识别回调是否密码学绑定、第三方程序账号密码接收、导出组件、动态主机约束、日志隐私与远控状态回读。
- SSL Pinning 的必要性、证书轮换影响；不可把“没有 Pinning”直接判成已证实攻击。
- R8/ProGuard keep，不能直接复制外部报告中过宽的 `-dontwarn` 规则；依赖瘦身要以真实构建体积及运行性能数据判断，不采信预计节省 70% 或 40% 内存。
- WorkManager **并非**安全关键定时器；露营/宠物模式不应通过手机轮询被描述为保障生命安全的车辆本地功能。

**本阶段唯一新增“安全相关”动作是证据标注和保持远控关闭，不引入密码、Token、第三方固定签名常量或线上车辆访问。** 参见 `10_TWO_REPORTS_RECONCILED.md`。
