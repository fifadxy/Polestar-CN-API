# Android v0.4.0-beta1

本版本按用户确认的优化范围制作，继续使用 `android-polestar-assistant-main` 分支。

## 使用

1. 安装 APK，可覆盖同签名的 alpha2。首次启动直接进入中国区手机号＋密码登录页，不再显示区域选择弹窗。
2. 已安装用户提供的原模板 APK 时自动使用该样本；否则点“导入模板 APK”，选择原文件完成一次性导入。样本必须匹配 SHA-256 `8cae07a3b5c6050487443914ebb55b1d2f2f26e258f4b369837f2b88de052735`。只把兼容参数经本机 Keystore 加密保存，不复制模板 APK，不向 GitHub 上传兼容参数。密码不持久化。
3. 登录成功后发现本人车辆，默认进入车辆控制首页。多车可点击车辆名称选择。首页和 Widget 均不再用演示数值补空缺；未知显示 `—` 或“未知”。
4. 门锁、尾箱、空调和净化卡片进入明确的动作选择，再通过 Android `BIOMETRIC_STRONG` 系统验证。设备支持的强指纹/强生物识别可用；不支持、未录入、取消或失败均不执行。
5. 设置可选择中文、English 或跟随系统，显示模式可选择浅色、深色或跟随系统。Widget 的文字始终为英文。
6. “常驻车辆状态通知”默认关闭。开启后需允许 Android 13+ 通知权限；通知显示电量/充电、空调/净化、数据采集时间和 Token 最近签发/刷新时间。静默低优先级保留状态图标，锁屏隐藏具体内容，展开才显示完整信息。折叠高度由 Android 决定。

## 后台与效率

- 前台服务只承载用户主动开启的常驻通知，不持有 WakeLock，不做高频轮询。
- 系统 JobScheduler 约每 30 分钟批量调度读取，网络不可用/Doze/厂商电池限制会延迟。开机或覆盖安装后恢复已启用的选项。退出登录后停止联网读取。
- 控制和刷新共享串行网络队列，防止并发误操作；相同 host 复用 gRPC channel，一分钟闲置进入空闲状态；写操作关闭自动重试。
- 每次控制只发送一次，然后最多四次只读状态回读。服务器接受与车辆状态确认分开呈现。回读失败不会重发控制。
- 首屏控制采用弹性空间分配；短屏横向采用一行四控件。详情和设置可滚动。字体放大到极端值时仍需设备无障碍验收。
- Token 的刷新时间作为无密钥元数据读取，避免通知每次更新解密整个会话。
- 车辆图片使用 WebP。英文和数字采用 PDF 内嵌同族 Lato（开源完整字体），中文由系统字体回退；PDF 未提供 Polestar 专用字体文件。未把替代字体称为官方字库。

## 素材来源

- 符号：用户提供的 `Polestar_Design_Reference_2026_EN_v2.pdf` 内的直接公共素材，保留像素比例与明暗版本；自适应启动图标留出安全区域。
- Polestar 2 俯视图：用户提供模板 APK 的 `vehicle_top.png`，等比例转换 WebP。只在车型名称包含 2 时使用，其他车型显示品牌符号，不混用车型图片。
- 功能图标：独立制作的细线 VectorDrawable，属于工程实现图标，不声称是官方图标路径。
- Lato：Google Fonts，许可证随 APK 放在 `assets/licenses/Lato-OFL.txt`。

## 验证边界

本地构建、JVM 协议检查、Robolectric 启动/屏幕布局/缓存/语言/通知回归与 Android Lint 分别记录在知识库中。云环境没有 USB/KVM 和用户车云凭据，无法完成真机指纹与中国区实车账号的端到端验收；编译通过不能代替真实登录和车端动作验证。尾箱、上锁、净化的请求按模板方法体映射实现，具体车型支持情况需实际确认。
