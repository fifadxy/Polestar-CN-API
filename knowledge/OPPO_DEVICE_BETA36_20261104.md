# beta36 真机版 / 模块 2.0

基线：beta35 /149（408e57def2f738e86ee27f40cb8cef1bad8982de）。本版：0.9.7-beta36-device /150；内置 Bridge 2.0.0 /33。

## 本版用途

系统卡片使用真实登录、真实车辆和现有极星中国区命令接口。构建明确关闭 Mock SDK。真实请求仍服从本应用的逐操作验证和状态新鲜度检查。

原有设备卡、车型映射、4×2路由和虚拟会话开关归并为“启用系统车辆接入”。LSPosed 管理器设置入口与主程序 OPPO 互联入口打开同一个页面。重复的模拟测试按钮和 Watch 探测开关移出主流程；官方 SDK 与车型参数保留在高级菜单。

## 链路及证据

* 负一屏/设备空间：原生按钮 → 精确事件拦截 → 主程序一次性 PendingIntent → 当前真实车辆与验证策略检查 → 已有极星接口 → 状态回读。
* 完整控制面板：锁车、解锁、空调、净化、尾门、车窗、鸣笛、闪灯。补齐了此前在 gateway/shortcut 白名单中丢失的车窗命令。
* CarLink 本机面板：用户点击 Root 按钮，用 root 身份启动本机实际解析的受保护 Activity，并携带明确的本机面板标记。LSPosed 只处理标记过的实际 ControlRouterActivity，在正常生命周期之后尝试挂载真实车辆控制面板。宿主回报单独记录面板时间、模块版本和失败原因。
* IOT：仍显示 PackageManager 观测的权限结果。Root 启动受保护入口不等于给 PsAssistant 授予 signature 权限；本版不伪造该结果。
* 官方 OCS SDK：本机桥接通道不要求官方 SDK 身份。公开 CI 构建使用 API 契约桩，未包含官方 SDK 实现，官方 OCS 通道不能据此验收；本机 Root 面板不是官方云端绑定。
* OPPO Watch/数字钥匙：没有在本版完成适配，设置不再暗示已经支持。

CarLink 如在挂载前因自身业务逻辑退出或跳转，面板回报将不会出现。本版保留该失败证据，不把 am start 的退出码当作打通。

## 真机测试顺序

1. 同签名覆盖安装。在 LSPosed 只启用主程序内置模块；作用域至少包含 MyDevices、AssistantScreen、CarLink 及既有 QuickApp 运行环境。更新模块后重启手机。
2. 在主程序登录中国区账号、选车并刷新一次，确认主程序原有控车正常。
3. 打开 OPPO 互联（现为“系统车辆接入”），点击“检查并配置接入”。核对车辆会话和可控状态。
4. 先点击“真车控制测试”，自行选择一条命令；再在负一屏 4×2 设备卡上点击对应按钮。不要一次自动执行所有车控。检查命令时间、SERVER_ACCEPTED 和 VEHICLE_CONFIRMED；鸣笛/闪灯需现场观察。
5. 点击“CarLink 本机面板（Root）”。返回设置核对 CarLink 面板回报时间是否晚于本次点击，不能只看历史 true。
6. 任一步失败，从“诊断与导出”复制文字摘要，或生成 ≤2MB ZIP。摘要只保留动作名称、执行阶段和时间，不包含完整 VIN、Token 或账号凭据。

开关关闭后，本应用 Provider/命令门禁立即关闭；宿主已有视图与 Hook 的撤销仍需重载进程。“重载系统组件”逐个核对已安装组件的 root 停止结果，不再用一条多命令 shell 的最后退出码代表全部成功。

## 耗电

打开设置和卡片只读缓存；手动刷新才读取车辆，控制后的状态回读沿用现有有界实现。没有为 CarLink 面板新增扫描、车况定时器或循环命令。手机、车辆 12V 与手表长续航仍需实际设备测量。
